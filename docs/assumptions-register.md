# Engineering assumptions and abstraction register

This register records the source basis and limits for the project's principal
models and automotive feature abstractions. Unless an entry explicitly names a
measured dataset, its numeric values are design or simulation assumptions and
are not calibrated target-cell or vehicle parameters.

| Area | Source basis | Working assumption | Boundary and verification evidence |
|---|---|---|---|
| Cell chemistry | PyBaMM Prada2013 LFP parameterization and the project decision log | Use a reference LFP/graphite cell to exercise pack-level behavior | Not a parameter fit to the target EVE cell. Parameter source and integrity are checked by `tests/unit/test_battery_parameter_integrity.py`; electrochemical parameter applicability remains unverified. |
| EVE LF100LA rated limits | EVE LF100LA Version A specification recorded in `models/battery-parameters/eve_lf100la_vA.json` | Rated capacity, voltage, cutoff, C-rate and temperature values represent the selected nominal cell | The same JSON leaves DC resistance, OCV curve, RC and thermal parameters null; do not infer manufacturer validation of simulation values. |
| Equivalent-circuit model | `models/battery-parameters/lf100la_ecm_assumptions.json` | First-order Thevenin model with synthetic R0/R1/tau and illustrative OCV-SOC table | Values are explicitly marked synthetic and not manufacturer validated. HPPC-style, parameter-identification and discharge scripts verify internal consistency only. |
| Cell-to-pack construction | `models/pack-model/cell_configuration.py` and 16S scenario configuration | Series-connected cells share pack current; cell SOC/capacity/resistance can vary independently | Does not represent parallel strings, wiring parasitics, fuses, thermal coupling or production pack tolerances. 16S behavior and weak-cell injections are exercised in SIM-001 to SIM-003. |
| SOC | Coulomb-counting and OCV fusion implementations; UConn and Seville datasets for research labels | Initial SOC, usable capacity and current integration are supplied assumptions; OCV correction is illustrative in the LFP flat region | Drift and flat-plateau ambiguity remain. Seville-derived labels are within-discharge coulomb throughput for one cell; no independent multi-cell SOC ground truth is present. |
| SOH and RUL | UConn LFP/graphite RPT capacities and pulse records; synthetic 16S degradation scenarios | Capacity SOH is reference discharge capacity divided by 1.2 Ah nominal; RUL targets the first observed point at or below 80% | Pulse resistance is an approximate pulse-start delta-V/delta-I feature, not separately measured Re/Rct. Whole-cell and whole-protocol-group scores are research-only; RUL errors remain large. |
| Sensor behavior | Seeded noise, bias, invalid and missing-channel injection scenarios | Error magnitudes and fault patterns are chosen to exercise software behavior | Not derived from calibrated sensor specifications or physical fault distributions. SIM-005 to SIM-007 and SIM-012 verify selected cases and repeatability. |
| Thermal management | Static temperature scenarios and provisional temperature coefficient in the pack diagnostics | Temperature changes resistance/diagnostic inputs according to configured scenario relationships | No heat generation, thermal mass, cooling, propagation or runaway model is claimed. Unit and integration checks verify classification/interlocks only. |
| Insulation monitoring | Software status abstraction and configured limits in `software/diagnostics/lfp_16s_insulation_monitor.py` | Valid/warning/fault/unavailable status can be injected as an input | No physical insulation measurement or calibrated threshold is represented. SIM-014 tests status transitions and invalid/stale inputs. |
| SOP | First-order ohmic voltage/current limit calculation | Per-cell voltage, resistance, capacity, SOC and temperature are available and valid | No polarization dynamics or current actuator is modeled; output is advisory. `tests/unit/test_lfp_16s_state_of_power.py` checks validity and derating. |
| SOS and fault severity | Rule-based summaries in supervisory and state-of-safety modules | Explicit BDU, sensor, thermal, insulation and diagnostic states have configured priority | Severity/evidence grades are categorical, not calibrated probabilities; advisory logic cannot override the modeled protection BDU. SIM-017/018 and supervisory fault tests verify precedence. |
| BDU/contactors | `software/protection/lfp_16s_protection_bdu.py` and mode-level abstraction | State transitions and actuator command values are simulated from input thresholds | No contactor dynamics, independent safety hardware, timing, arc interruption or physical fault coverage is established. SIM-016/017 and BDU tests cover modeled transitions. Software precharge defaults (2-V delta, 5-s timeout) differ from the hardware example (3 V, 1 s); reconcile before baselining requirements. |
| Precharge R-C example | `hardware/circuit-definition.md` and `models/electrical/precharge_rc.py` | Ideal 58.4-V source, 100-ohm resistor, 2-mF DC link, 3-V main-close delta, 1-s timeout | SIM-021 checks the analytical R-C response and a blocked-path fail-open case. It omits source impedance, load/leakage, component tolerance, switch/contactor dynamics, thermal coupling and hardware. Values remain illustrative. |
| Dynamic-load SOC initialization | `software/estimation/soc_drive_cycle.py` and `models/battery-parameters/lf100la_ecm_assumptions.json` | Deterministic synthetic pulse/regen current, ideal sensing, and 15-percentage-point initial SOC error | SIM-022 compares coulomb counting with one rest-time OCV correction. The profile is not WLTP/UDDS; the ECM/OCV table is synthetic; LFP flat-plateau observability limits correction. |
| Hardware cell basis | Project model `models/battery-parameters/eve_lf100la_vA.json` names EVE LF100LA Version A, 100 Ah, 3.2 V | Draft 16S voltage endpoints are 40.0–58.4 V | The model cites a third-party-hosted copy; verify controlled cell-lot specification before release. No hardware thresholds have been commissioned. |
| Hardware current target | Draft 50 A continuous / 100 A for 30 s with external contactors and 100 µΩ shunt target | Conservative project-level design assumption aligned to software's 50 A scenario and below cited cell maxima | Not an approved vehicle/load rating; pack fault current, contactor interruption, fuse, shunt thermal and precharge are not sized. See `hardware/circuit-definition.md`. |
| Hardware validation | Scope limited to schematic/PCB design; no fabrication or physical battery testing planned | CAD checks and design review only | Hardware must remain labeled unbuilt/unvalidated; no safety, compliance or vehicle qualification claim. |
| Balancing | `models/balancing/lfp_16s_passive_balancing.py` and `models/balancing/lfp_16s_switched_cap_active_balancing.py` | Passive bleed is compared with a generic shared-capacitor-bank transfer, using illustrative voltage, capacity, current and thermal assumptions | Active model is not circuit-level or component-calibrated. One 16-cell SOC mismatch scenario compares time and modeled losses; no universal efficiency or hardware performance is claimed. Unit interlocks and the comparison experiment provide software-only evidence. |
| Message and CAN interface | Versioned transport-independent message schema | Units, scale, cell index, timestamp, quality and stale status are represented in software | No CAN identifier, frame encoding, bus timing, synchronization or transceiver is implemented. SIM-017 checks schema and freshness behavior. |
| Cybersecurity and lifecycle | Command authorization and hash-chained JSONL battery-passport abstractions | Role allow-lists and append/replay records are testable software inputs | The chain detects edits/reordering but cannot detect whole-file replacement or truncation without an external anchor. No cryptographic authentication, secure boot, durable storage or regulatory compliance is claimed. SIM-019/020 exercise modeled paths. |
| AI predictions | Supplied NMC/NMC-LCO assets plus UConn LFP RPT-derived SOH/RUL forests | Inputs must match the documented chemistry/domain and feature contract | All AI output is `RESEARCH_ONLY`/warning quality. Models do not command balancing or protection. LFP SOC AI is disabled pending adequate independent validation. |

## Change control

When a model parameter, software boundary, or data source changes, update the
relevant row and its verification evidence. A passing software test demonstrates
the modeled behavior only; it does not convert a provisional assumption into a
measured or hardware-validated value.
